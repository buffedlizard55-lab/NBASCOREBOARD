How this page gets its data

NBA's own CDN refuses every origin except nba.com (measured: HTTP 403 for this site's origin), NBA's S3 mirror sends no CORS header, and stats.nba.com never answers a cloud runner. So a GitHub Actions pipeline fetches the official feeds server-side and commits the responses next to this page. The browser then reads them same-origin — 100% official NBA data, no third-party aggregator, no manual checking.

Measured access evidence

These files are written by the probe workflows on a real network egress — every status code in them is a recorded response, not an assumption.

  • endpoint-probe.json — first pass: which official hosts answer at all (CDN 200/403 pattern, stats.nba.com timeouts, data.nba.net TLS failure).
  • access-probe.json — proves the 403 is triggered by the request's Origin, and which header set unlocks HTTP 200.
  • browser-transport-probe.json — a page like this one cannot read the CDN (403 with its own Origin, HTTP/1.1 and HTTP/2).
  • s3-probe.json — NBA's S3 mirror returns identical bytes but no CORS header.
  • deep-probe.json — header sensitivity, stats.nba.com recipes, schedule file contents.
  • coverage-probe.json — how far back CDN game files go (2019-20 confirmed; 2018-19 and older absent).
  • cards-probe.json — the nba.com game page server-renders full cards for any date (1996 example included).
  • sync-log.json — every pipeline fetch: endpoint, HTTP status, bytes, games/actions.

Game ID format (used in links and archives)

00X YY NNNNN — 001 preseason · 002 regular season · 003 All-Star · 004 playoffs · 005 play-in · 006 NBA Cup final; YY = season ending year. Example: 0041500407 = 2015-16 playoffs, Game 7.

Known limitations (measured, not assumed)

  1. Browsers cannot read NBA JSON directly. cdn.nba.com answers 403 to any request whose Origin is not nba.com — measured with and without a referer, over HTTP/1.1 and HTTP/2. That is why this page reads committed data instead of calling the CDN itself.
  2. stats.nba.com is unreachable from cloud runners. Every documented header recipe timed out (45 s) from GitHub Actions; historical stats beyond the CDN live-data era (2018-19 and earlier for box scores) are therefore not available here.
  3. Freshness is bounded by the pipeline. Live reads land in the published snapshot every ~10 minutes. A 10-second-refresh page is possible only with your own relay in front of the official feeds (see README).
  4. Standings are not published. The official standings come from stats.nba.com (blocked) and nba.com/standings loads its table client-side; no official standings source answered, so none is shown — instead of showing numbers from a third party.
  5. Full play-by-play archives start at final. Box scores and play-by-play are archived for games from 2019-20 onwards once a game is final; for other dates the board shows period scores, leaders and a link to the official game page.

Data ownership: all data belongs to the NBA. This project reads official public endpoints that nba.com itself uses, stores the responses unchanged (or with a documented field subset), and links every number back to its source.
