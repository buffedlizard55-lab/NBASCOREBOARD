The network observations below were recorded **2026-09-25**; access policy, schema and scores can change.

## How automated checks work — and their limit

`python3 tests/verify_data.py` checks **every** published file with a `_sync` block for the NBA-owned endpoint expected at its path, official-byte fingerprint shape, stored-content hash, game ID/date consistency, sparse calendar date counts (including explicit zero versus missing key), final PBP game-end/final score, manifest paths/counts and cross-source team/score joins *where both files exist*. It fails on any internal mismatch. It **cannot** recompute the official response hash without new NBA network access; it does not certify old `_sync.sourceSha256` values independently. Re-run an NBA fetch to check those bytes. `python3 -m unittest discover -s tests -p 'test_*.py'` mocks official-shaped feeds (including swapped IDs, malformed date cards, PBP lag and incomplete UTC-yesterday games). `npm --prefix tests test` boots the real site against checked-in NBA files and a **clearly synthetic** in-memory live game; test game states are never published as facts.

The ingestion job requires: (1) an official `scoreboard.gameDate` and `games` array, with a nonempty schedule-backed night not replaced by an empty live feed; (2) ten-digit game IDs and two actual team identities; (3) date cards whose ET date equals the requested date, with no conflicting server-selected date, calendar count or empty page when a published NBA schedule lists games; (4) box/PBP game IDs matching the request; and (5) for a final, an NBA `Game End` action and running PBP score matching the final official box score. When a second source is available, team IDs and scores in a final date card are compared with the NBA box score *before it is archived* and against any previously stored box. If any fail, the job records a `FAILED` / `INVALID` / `MISMATCH` step instead of replacing good data with false values; the Action fails after committing failure evidence and the site flags the latest published issues. **An unavailable comparison is not marked verified.**

## Manual review checklist for the next live-game night

1. Open the [deployed site](https://buffedlizard55-lab.github.io/NBASCOREBOARD/) and the [NBA.com games page](https://www.nba.com/games) for the same Eastern date. Confirm the game ID, teams, score, period and capture time; don't just see a red badge and assume real-time.
2. Check [Actions → Sync official NBA data](https://github.com/buffedlizard55-lab/NBASCOREBOARD/actions/workflows/sync-nba-data.yml) for a **schedule** event, successful official response/status and a published commit. A manually dispatched check is useful, but does not establish that cron works.
3. Open [`data/index.json`](data/index.json): compare `heartbeat.lastSuccessfulLiveUtc` with the actual Action and `live.fetchedAtUtc` with the displayed numbers. Open [`sync-log.json`](data/verification/sync-log.json) for errors or zero-game anomalies.
4. Open `data/games/<official gameId>/{boxscore,playbyplay}.json` for that live game and compare with its actual NBA.com **Box Score** and **Play-by-Play** tabs. Verify last action clock/score, not just its existence. Never infer an absent NBA CDN file is a played zero-score game.
5. Once Final, confirm the published scoreboard, date card, box score and PBP end score/team IDs agree. If they do not, record the irregularity with all NBA links and let the pipeline retry; do not patch numbers by hand.

**Open:** all-date/full-history completeness, observed live-night reliability and the GitHub Pages duplicate-publisher configuration. These are limitations, not already-verified successes.
